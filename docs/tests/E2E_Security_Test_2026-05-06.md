# MacOSUI テスト仕様書 (Test Cases)

本ドキュメントは、機能（ウィジェット）単位での動作確認と、`SystemSettings`（システム設定）との連携、およびインフラセキュリティを網羅的に検証するためのテスト仕様書です。
テスト用の専用ブランチ `test/e2e-security-review` 上で実施し、結果を追記して管理します。

## テスト実行ステータス凡例
- `[ ]` 未実施 (Not Started)
- `[🏃]` 実行中 (In Progress)
- `[✅]` パス (Pass)
- `[❌]` フェイル・要修正 (Fail)

---

## 1. インフラストラクチャ・セキュリティ監査 (Infrastructure & Security)

### 1-1. 秘匿情報とデータの保全
- `[✅]` **TC-INF-01**: `Gemini API Key` や `Client Secret` がフロントエンドのソースコード（`dist/assets/*.js`）やネットワーク通信（APIレスポンス）に露出していないことを確認する。
- `[✅]` **TC-INF-02**: Dockerコンテナ内で `.env` や `server/development.env` などの環境変数がセキュアに読み込まれていることを確認する。
- `[✅]` **TC-INF-03**: `db.json` および `published_reports` などのSQLiteデータがVolumeマウントにより永続化されており、コンテナ再起動時にもデータが消失しないことを確認する。

### 1-2. VPS・ネットワークセキュリティ
- `[✅]` **TC-INF-04**: さくらVPSのパブリックIPに対し、不要なポート（例: 8080, 22以外）が外部からアクセスできないようファイアウォールでブロックされていることを確認する。
- `[✅]` **TC-INF-05**: NginxリバースプロキシがHTTPS(SSL)で正しくルーティングを行っており、安全なCookie（HttpOnly, Secure属性等）が発行されていることを確認する。

## 2. 認証・RBAC（Role-Based Access Control）

### 2-1. APIエンドポイント保護
- `[✅]` **TC-AUTH-01**: 未認証（シークレットウィンドウ等）で `/api/research/publish` や `/api/knowledge`、`/reports/1234.html` に直接アクセスした場合、データが返却されず401エラー（またはログイン画面へのリダイレクト）になることを確認する。

### 2-2. Passkeyログインと権限分離
- `[✅]` **TC-AUTH-02**: **一般ユーザー（User）**アカウントでPasskeyログインを行い、正常にデスクトップ画面に遷移できることを確認する。
- `[✅]` **TC-AUTH-03**: **管理者（Admin）**アカウントでPasskeyログインを行い、正常にデスクトップ画面に遷移できることを確認する。
- `[✅]` **TC-AUTH-04**: 一般ユーザーでログイン中、`SystemSettings` 内の「管理者設定タブ（APIキーやテナント管理など）」が表示されない、または変更リクエストがサーバー側で拒否(403)されることを確認する。

## 3. ウィジェット別 結合テスト (Widgets & System Settings)

このセクションでは、各ウィジェットが単体で動作するだけでなく、`SystemSettings`（システム設定）で定義した値が正しく機能に反映されるかを中心にテストします。

### 3-1. System Settings（システム設定）ウィジェット
- `[✅]` **TC-SYS-01**: システム設定ウィジェットを開き、使用する「Deep Research用モデル」「HTML/SVG用モデル」「Infographic用モデル」を変更・保存できることを確認する。
- `[✅]` **TC-SYS-02**: 保存先となる「Google Drive Folder ID」を変更・保存できることを確認する。
- `[N/A]` **TC-SYS-03**: 「システムアクティベーション状態」のトグルが正常に切り替わり、非アクティブ時はアプリの機能が制限されることを確認する。（※該当UIは現在削除されているためテスト対象外）

### 3-2. Deep Research ウィジェット
- `[✅]` **TC-DR-01 (設定連動)**: System Settingsで変更したAIモデルが、Deep Research実行時に正しく反映され、実行後の「対象モデル」サマリーにそのモデル名が表示されることを確認する。
- `[✅]` **TC-DR-02 (設定連動)**: System Settingsで変更したDrive Folder IDの場所に、最終成果物（HTML/SVG/Infographic）がアップロードされることを確認する。
- `[✅]` **TC-DR-03 (E2E完走)**: リサーチ→HTML生成→Drive保存→ナレッジベース登録までの一連のフローが途中でクラッシュすることなく最後まで完走することを確認する。
- `[✅]` **TC-DR-04 (直接変換)**: 長文テキストを入力し「HTML/SVG直接変換」モードで実行した場合、タスク1（リサーチ）がスキップされ、正常に変換・保存・ナレッジベース登録が行われることを確認する。
- `[✅]` **TC-DR-05 (レジューム)**: 処理実行中にブラウザをリロードしても、前回の途中状態から問題なく再開（Resume）できることを確認する。

### 3-3. Knowledge Base（図書室）ウィジェット
- `[✅]` **TC-KB-01**: Deep Research（TC-DR-03）で作成されたデータが、Knowledge Baseの一覧に新しい記事として即時表示されることを確認する。
- `[✅]` **TC-KB-02**: 左側のタグ一覧から「DeepResearch」や「HTML」をクリックした際、正しく記事が絞り込まれることを確認する。
- `[✅]` **TC-KB-03**: 検索バーにキーワードを入力し、セマンティック（フルテキスト）検索が正しく機能することを確認する。
- `[✅]` **TC-KB-04 (Secure URLルーティング)**: 記事内の `[🌐 **Webページとして開く (Secure URL)**]` リンクをクリックした際、新しいタブで作成したHTMLレポートが文字化けやレイアウト崩れなく表示されることを確認する。

### 3-4. Gemini Chat ウィジェット
- `[✅]` **TC-GEM-01 (一般チャット)**: 通常のプロンプトを入力し、Geminiモデルからの応答が正常に返ってくることを確認する。
- `[✅]` **TC-GEM-02 (RAG/ナレッジ連携)**: ナレッジベース内の情報を参照するプロンプト（例: 「先日保存した○○について教えて」）を入力し、RAG機能が動作して該当ドキュメントの文脈を踏まえた回答が生成されることを確認する。
- `[✅]` **TC-GEM-03 (モデル切り替え)**: チャット画面内の設定やシステム設定でモデルを変更した場合、そのモデルで推論が行われることを確認する。

### 3-5. Google Schedule (Calendar) ウィジェット
- `[✅]` **TC-SCH-01 (表示と連携)**: ウィジェットを開いた際、Google Calendarのイベントが正常に取得・表示されること（現在の実装レベルでの基本表示）を確認する。
- `[✅]` **TC-SCH-02 (APIエラーハンドリング)**: 認証エラーやGoogle APIの制限などで予定が取得できない場合、UI上で適切にエラーハンドリング（フォールバック表示やエラーメッセージ）が行われることを確認する。

### 3-6. Finder / Browser ウィジェット
- `[✅]` **TC-FB-01**: FinderウィジェットからGoogle Driveのファイル一覧が正しく取得でき、ダブルクリックで開けることを確認する。
- `[✅]` **TC-FB-02**: Browserウィジェットで任意のURL（またはナレッジベース内のリンク等）を開いた際、正しくIframe内でレンダリングされることを確認する。

## 4. チャット機能強化および複数RAGフォルダ対応 (Chat Enhancements)

### 4-1. プリセット機能とGrounding
- `[ ]` **TC-FEAT-01**: チャットのデフォルトが「Normal Chat (Grounding ON)」になっており、Google検索を利用した最新情報が回答されること。
- `[ ]` **TC-FEAT-02**: 「📰 今週のAI3大ニュース」ボタンをクリックするとプロンプトが自動入力され、Web検索を通じて最新のニュースが回答されること。

### 4-2. 複数RAGフォルダの管理と同期
- `[✅]` **TC-FEAT-03**: System Settingsで複数のRAGフォルダ（名称とID）を登録し、保存できること。
- `[✅]` **TC-FEAT-04**: 「Sync Now」を実行し、登録した複数フォルダのファイル群がそれぞれ正常に同期されること。
- `[✅]` **TC-FEAT-06 (重複エラー防止)**: System Settingsで既に登録されているGoogle Drive Folder IDを追加しようとした際、アラートが表示されてブロックされること。また重複ファイルがある場合でもSyncの誤警告が出ないこと。

### 4-3. フォルダ指定RAGの切り替え
- `[ ]` **TC-FEAT-05**: Gemini ChatのSELECTボックスに登録したRAGフォルダが表示され、選択して質問した際、他のフォルダのファイルが混ざらず指定フォルダの情報のみで回答されること。

### 4-4. チャットプリセットとFAQのカスタマイズ
- `[ ]` **TC-FEAT-07**: System Settingsでコンテキストごと（通常チャット、Grounding、各RAGフォルダ）にプリセットプロンプトを登録・編集でき、Gemini Chat側で選択されたモードに応じて適切なプリセットボタンが動的に切り替わって表示されること。
- `[ ]` **TC-FEAT-08**: System Settingsで自動収集されたRAG FAQ（人気のクエリ）の一覧を表示でき、不要な重複クエリの削除やテキストの編集が正常に行えること。
