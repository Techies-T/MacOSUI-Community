# MCP サーバーセキュリティ標準設計ガイドライン (ZTA/A2A 準拠)

本ドキュメントは、プロジェクト内において新規に MCP (Model Context Protocol) サーバーを構築、または既存のサーバーを拡張する際に、強制適用されるセキュリティおよびトランスポートの標準仕様ガイドラインです。

ゼロトラストアーキテクチャ (ZTA) に適合させ、各エージェントおよびサービス間の安全な連携を保証するため、以下の設計基準を必ず遵守してください。

---

## 1. ゼロトラスト認証 (ZTA / A2A Token Verification)

MCP サーバーへのすべての接続・リクエストは、Agent-to-Agent (A2A) 認証フローに基づいて、厳格に暗号化および検証されなければなりません。

### ① Client Credentials によるトークン発行
* **エンドポイント**: `POST /api/mcp/[service-name]/token`
* **動作仕様**:
  * クライアントは `client_id` と `client_secret` を使用してアクセストークンを請求します。
  * `JWT_SECRET`（`MacOSUI/server/development.env` などの環境変数から解決される共通鍵）で署名された一時的な JWT アクセストークンを発行します。
  * トークンの有効期限は **1 時間 (3600秒)** とし、発行完了のレスポンスに `expires_in` を明記します。
  * 発行される JWT ペイロードには、適切なスコープ/クレーム（例: `type: 'agent_token'`, `aud: 'app:[service-name]'`）を付与します。

### ② JWT 署名と有効期限の厳格検証 (ZTA PEP)
* **ミドルウェアでの検証**:
  * トークンが正しく `JWT_SECRET` で署名されていること、有効期限 (exp) 内であることを確認します。
  * 対象オーディエンス (`aud`) や発行元、トークンタイプ (`type === 'agent_token'`) などの RFC 8693 に基づくコンテキスト検証を行い、適合しないリクエストはすべて `403 Forbidden` / `invalid_token` で即座に遮断します。

---

## 2. トークン有効期限切れへの自動対応 (サイレントリフレッシュ)

接続するクライアント（またはエージェント）がバックグラウンドで自動的に新しいトークンを再取得（サイレントリフレッシュ）できる設計にします。

* **動作仕様**:
  * トークンの有効期限切れエラー (`invalid_token`) が返された場合、クライアント側が再度 `client_id` と `client_secret` を用いてトークンを再取得し、自動で処理を再試行（リトライ）できる構成を考慮した設計にします。
  * サーバー側は、これらの一時的な再接続をスムーズに受け入れられるよう、ステートレスな設計を心がけます。

---

## 3. SSE (Server-Sent Events) トランスポート通信

MCP メッセージのやり取りには、標準の stdio 方式ではなく、HTTP 経由の双方向通信である **SSE (Server-Sent Events) 方式** を採用します。これにより、コンテナ間通信や異なるネットワーク間でのセキュアなやり取りを実現します。

### ① 接続エンドポイント (`GET /sse`)
* クライアントから ZTA 認証トークン（クエリパラメータ等）を伴う接続要求を受け、持続的なイベントストリームを確立します。
* 接続時に一意 of `sessionId` (Session ID) を発行し、トランスポートマップでセッションを永続的に管理します。

### ② メッセージ送信エンドポイント (`POST /message`)
* クライアントが `sessionId` を指定して MCP 要求 (JSON-RPC) をポストします。
* サーバー側は認証ヘッダー (`Authorization: Bearer <token>`) を検証し、該当セッションの SSE ストリームを通じて MCP レスポンスをプッシュします。

---

## 4. データベースの整合性と親ストーリー連動

アジャイル開発進捗などの共有データを扱う場合、データの不整合を防ぐため、以下の自動整合ロジックを実装します。

* **状態変化の制限**:
  * レビュー対象などのデリケートな変更（承認など）を行う場合、対象レコードの現在の状態（例: `status === 'review'`) を事前チェックし、不正な遷移を拒否する安全ブレーキ機能を実装します。
* **親要素への自動伝播**:
  * サブタスク（詳細タスク）の状態が変化した際、親バックログ（ユーザーストーリー）の状態を自動再評価し、全体の完了・進行状況を自動同期します。

---

## 5. 推奨する技術スタックとモジュール構成 (Node.js テンプレート)

* **Express**: 認証・トークン発行・SSE エンドポイントのルーティング管理。
* **@modelcontextprotocol/sdk**: 公式 MCP SDK (`Server`, `SSEServerTransport`) を使用。
* **jsonwebtoken**: JWTの生成・検証。
* **sqlite3**: 軽量でファイル永続性のある SQLite の利用。
